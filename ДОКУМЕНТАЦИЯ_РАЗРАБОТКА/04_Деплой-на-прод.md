# Деплой кастомной формы на прод

## Что задеплоить (файлы)

```
site/core/elements/snippets/sendLeadToB24.php
site/core/components/chunks/ObrForm/modalForm.tpl
site/assets/components/obr-form/form.css
site/assets/components/obr-form/form.js
site/assets/components/obr-form/icons/*.svg   (6 файлов)
```

Эти файлы коммитятся в git (попадают в обычный deploy).

## Что НЕ деплоить

- `site/core/config/b24.config.php` — gitignored, **создать руками на проде**
- `site/core/cache/logs/b24_leads.log` — gitignored, создаётся автоматически
- Папки в корне репо (`ДОКУМЕНТАЦИЯ_РАЗРАБОТКА/`, `ОБРПРОФИ_АНАЛИТИКА/`, `ПРЕДЛОЖЕНИЯ_2026-04-30/`) — на прод не копируются (deploy-скрипты работают только с `site/`)
- `scripts/setup_obr_form.php` и другие диагностические скрипты — лежат в `scripts/` (не деплоятся)

## Что нужно сделать руками на dev/prod

### 1. Создать конфиг с URL вебхука

```bash
ssh severmarin_arkadiy@severmarin.beget.tech
cd ~/dev.obrprofi.ru/public_html/core/config/  # или ~/obrprofi.ru/public_html/core/config/
nano b24.config.php
```

Содержимое:
```php
<?php
return [
    'webhook_url' => 'https://ecoprof.bitrix24.ru/rest/26/<actual-token>/',
    'test_hosts' => [],   // на проде пусто — все лиды идут как боевые без префикса [ТЕСТ]
    'rate_limit_seconds' => 60,
    'log_file' => 'b24_leads.log',
];
```

⚠️ На проде `test_hosts` оставить пустым массивом, чтобы не было префикса `[ТЕСТ-LOCAL]` в TITLE.

### 2. Зарегистрировать элементы в MODX

Через скрипт `setup_obr_form.php` (один раз):

```bash
cd ~/dev.obrprofi.ru/public_html
php ../scripts/setup_obr_form.php   # путь к скрипту относительно сервера
```

Создаст:
- Категорию `ObrForm`
- Сниппет `sendLeadToB24` (статичный)
- Чанк `ObrFormModal` (статичный)
- Шаблон `clean-template`
- Ресурс `/ajax-lead`

Скрипт идемпотентный — если что-то уже есть, не дублирует.

### 3. Применить правки чанков Footer и catalogHeader в БД

Чанки `Footer` (id=3) и `catalogHeader` (id=47) в боевой базе — без правок наших. Их нужно обновить через `update_chunks_in_db.php`:

```bash
php ../scripts/update_chunks_in_db.php
```

Скрипт идемпотентный — если уже содержит наши маркеры, пропускает.

После этого применить:
- `update_cta_text.php`
- `update_hero_cta_v2.php`

(они меняют текст и стиль hero-CTA на категориях курсов)

### 4. Очистить кеш MODX

```bash
rm -rf ~/dev.obrprofi.ru/public_html/core/cache/[a-z]*
```

### 5. Проверить endpoint

```bash
curl -X POST "https://dev.obrprofi.ru/ajax-lead" \
  --data-urlencode "name=DeployTest" \
  --data-urlencode "phone=+71234567890" \
  --data-urlencode "channel=phone" \
  --data-urlencode "form_source=Deploy check"
```

Должен вернуть `{"ok":true,"lead_id":...}`. Лид в B24 — без префикса `[ТЕСТ-LOCAL]` (если на проде test_hosts пуст).

## Откат

### Если нужно срочно отключить новую форму

В `Footer.tpl` (чанк id=3 в БД) — закомментировать строку:
```html
<!-- [[$ObrFormModal]] -->
```

Или совсем удалить вместе с её комментарием. После очистки кеша новая форма пропадает с сайта (старая `#MdGl` остаётся работающей).

CTA в hero на категориях продолжат показывать кнопку «Подобрать программу», но клик не откроет модалку (т.к. её нет в DOM). Чтобы вернуть рабочий старый CTA, в `catalogHeader.tpl` (id=47):
1. Сменить `data-bs-target="#MdGlNew"` на `data-bs-target="#MdGl"`
2. Убрать `data-form-*` атрибуты
3. Вернуть текст «Консультация с менеджером»

Скрипт-откат можно написать (mirror к `update_hero_cta_v2.php`).

### Полный откат

```sql
-- Удалить наши элементы
DELETE FROM modx_site_htmlsnippets WHERE name='ObrFormModal';
DELETE FROM modx_site_snippets WHERE name='sendLeadToB24';
DELETE FROM modx_site_content WHERE alias='ajax-lead';
DELETE FROM modx_site_templates WHERE templatename='clean-template';
-- Категория ObrForm
DELETE FROM modx_categories WHERE category='ObrForm';
```

Удалить файлы:
```bash
rm site/core/elements/snippets/sendLeadToB24.php
rm -rf site/core/components/chunks/ObrForm/
rm -rf site/assets/components/obr-form/
rm site/core/config/b24.config.php
```

И вернуть Footer.tpl и catalogHeader.tpl к состоянию до правок (через git revert или восстановление из бэкапа БД).
