# Откат B24-форм вручную через админку MODX

Документ для ситуации: **наша ObrForm перестала принимать заявки** (например, упал webhook B24, или баг с frontend) и нужно срочно вернуть старую B24-форму. Без программиста, без SQL — только через UI админки MODX.

**Минимальный набор шагов** — 5 минут работы, восстанавливает приём заявок через B24-loader.

---

## Вход в админку

1. https://obrprofi.ru/manager/ — авторизация по твоим учётным данным
2. Слева — дерево «Ресурсы», вверху — меню «Элементы → Чанки» и «Элементы → Шаблоны»

---

## Вариант 1 — БЫСТРЫЙ (вернуть только модалку #MdGl)

Этого достаточно чтобы 90% кнопок снова работали как через B24.

### Шаг 1. Найти и отредактировать чанк `Footer`

1. **Элементы → Чанки** → найти **`Footer`** (id=3) в списке
2. Открыть на редактирование
3. Найти в коде блок:
```html
<div class="modal fade" id="MdGl" tabindex="-1" aria-labelledby="exampleModalLabel" aria-hidden="true">
  <div class="modal-dialog modal-dialog-centered">
    <div class="modal-content">
        <div class="bg-primary modal-header px-4 py-4">
            <div class="h6 fs-5 fw-bold modal-title text-light" id="exampleModalLabel">Консультация</div>
            <button type="button" class="bg-white btn-close opacity-100 p-3 rounded-circle shadow-sm" data-bs-dismiss="modal" aria-label="Close"></button>
        </div>
        <div class="modal-body px-0 py-5">

        </div>
    </div>
  </div>
</div>
```

4. В пустой `<div class="modal-body px-0 py-5">` **вставить** B24-loader (тот же, что был до 12 мая):

```html
<div class="modal-body px-0 py-5">
    <script data-b24-form="inline/310/8mtk1t" data-skip-moving="true">
    (function(w,d,u){
    var s=d.createElement('script');s.async=true;s.src=u+'?'+(Date.now()/180000|0);
    var h=d.getElementsByTagName('script')[0];h.parentNode.insertBefore(s,h);
    })(window,document,'https://cdn-ru.bitrix24.ru/b16716304/crm/form/loader_310.js');
    </script>
</div>
```

5. **Сохранить** чанк
6. Очистить кэш MODX: **меню Управление → Очистить кэш сайта** (или Ctrl+Shift+F5 на сайте)

После этого модалка `#MdGl` снова появилась. **Но кнопки на сайте сейчас открывают `#MdGlNew`, не `#MdGl`.** Чтобы вернуть кнопки — см. Шаг 2 ниже.

### Шаг 2. Вернуть кнопки (массово)

Это самое много работы — кнопок 150+ в разных местах.

Самый простой способ — **СНОВА открыть админку**, в каждом из чанков ниже найти `data-bs-target="#MdGlNew"` и заменить обратно на `data-bs-target="#MdGl"`:

**Чанки которые надо отредактировать** (Элементы → Чанки):

| Чанк | Что найти и заменить |
|---|---|
| `Navbar` (id=2) | `data-bs-target="#MdGlNew"` → `data-bs-target="#MdGl"` (несколько мест) |
| `contAdres` (id=40) | `data-bs-target="#MdGlNew"` → `data-bs-target="#MdGl"` (1 шт) |
| `msProduct.content.prod` (id=42) | `data-bs-target="#MdGlNew"` → `data-bs-target="#MdGl"` (1 шт) |
| `boxManager` (id=43) | то же |
| `boxComerch` (id=46) | то же |
| `catalogFooter` (id=48) | то же (2 шт) |
| `SaleCard.tpl` (id=66) | то же |
| `boxFormNews` (id=76) | то же |
| `tpl.msProducts.row.Obr.Modal` (id=78) | то же (несколько) |
| `catalogCard.tpl.modal` (id=92) | то же (2 шт) |
| `catalogHeaderDPO` (id=96) | то же (2 шт) |
| `catalogFooterDPO` (id=97) | то же |
| `ContentBannerSout` (id=101) | то же |
| `msProduct.content.PSK` (id=102) | то же |
| `boxCTABanner` (id=104) | то же |
| `boxGuaranteePSK` (id=106) | то же |
| `msProduct.content.PSK_partner` (id=115) | то же |

**Совет:** в админке MODX в каждом чанке использовать **Ctrl+H** (Replace) в редакторе кода. Заменить все вхождения.

После всех правок — **очистить кэш сайта**.

### Шаг 3. Для блог-статей и спецстраниц

В контенте 118 ресурсов тоже стоит `#MdGlNew`. Это **тяжелее** через UI — придётся каждую открыть и заменить.

**Альтернатива:** оставить как есть. Кнопки в блог-статьях будут открывать пустую модалку `#MdGlNew` (если её не существует) — а если её всё ещё есть из ObrForm, то откроется наша модалка. Главное чтобы открывалось хоть что-то.

## Вариант 3 — Только URL для AJAX-эндпоинта

Если форма ObrForm сама нормальна, но JS-эндпоинт `/ajax-lead` сломан — открой `assets/components/obr-form/form.js` (через FTP/SFTP) и временно подмени строку:

```js
var ENDPOINT_URL = '/ajax-lead';
```

На реальный B24-webhook URL прямо:
```js
var ENDPOINT_URL = 'https://b16716304.bitrix24.ru/rest/.../crm.lead.add.json';
```

(нужен правильный токен webhook). Это временный костыль, но позволяет ловить заявки минуя нашу серверную часть.

## Контрольный лист после отката

1. Открыть https://obrprofi.ru/povyshenie-kvalifikacii/pozharnaya-bezopasnost/ — кликнуть кнопку «Консультация» → должна открыться модалка
2. Заполнить форму, отправить → лид должен прийти в B24
3. Проверить лог: `ssh ...` → `tail ~/obrprofi.ru/public_html/core/cache/logs/b24_leads.log`

Если лог пустой / 0 заявок за час после восстановления — что-то не так с webhook. Тогда временно прислать заявку **по телефону** клиенту, пока разбираем.
