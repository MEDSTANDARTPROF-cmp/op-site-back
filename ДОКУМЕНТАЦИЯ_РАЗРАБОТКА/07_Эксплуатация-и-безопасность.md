## Безопасность формы — резюме

**Защита, которая стоит:**

1. **Honeypot** — поле `<input name="website">`, скрыто CSS. Боты заполняют его → отказ.
2. **Origin/Referer check** — endpoint `/ajax-lead` отклоняет запросы без `Origin: https://obrprofi.ru` или нашего поддомена. Возвращает `{"ok":false,"error":"invalid_origin"}`.
3. **Rate-limit** — 60 секунд между заявками с одного IP (`rate_limit_seconds` в `core/config/b24.config.php`).
4. **Обязательный consent** — без галочки согласия на ПД отказ.
5. **Серверная валидация** — телефон по regex, длина текстов, обязательные поля.
6. **`b24.config.php` не публичный** — лежит в `core/config/`, права 600 на сервере. Через браузер не читается. В `.gitignore` — не уходит в коммиты.

**Что под угрозой:**

| Риск | Митигация |
|---|---|
| Утечка `b24.config.php` (через .git, бэкап файлов в неправильное место) | `.gitignore` + права 600 на проде. Если файл всё-таки утёк — пересоздать webhook в B24 и обновить URL в `b24.config.php`. |
| Spam через подделку `Origin` хедера | Rate-limit срежет массовость. Если пойдёт серьёзный спам — добавить reCAPTCHA или Yandex SmartCaptcha (5 минут работы). |
| DDoS на эндпоинт | Cloudflare WAF не используется (решение клиента). Защита на стороне Beget — проверить включён ли `mod_security`. |
| Утечка DB-пароля прода | Сейчас лежит в `scripts/deploy-courses-to-prod.sh` в открытую — рассмотреть переход на `.env` файл, gitignored. |

**Чего НЕ боимся:**
- SQL injection — сниппет не делает raw-SQL, всё через MODX-абстракции
- XSS — данные не возвращаются на страницу, только в B24
- CSRF — Origin check защищает

## Частые операции

### Перевыпустить webhook B24
1. В Битрикс24 → Разработчикам → Входящий вебхук → старый деактивировать, новый создать с правом `crm`
2. Обновить URL в `~/obrprofi.ru/public_html/core/config/b24.config.php`
3. Очистить кеш: `rm -rf ~/obrprofi.ru/public_html/core/cache/[a-z]*`

### Изменить SEO-статью на одной категории
- Через MODX-админку → Ресурс категории → TV `seo_article`
- Или через скрипт: положить `.html` в `scripts/faq/`, прогнать `load_partition_*.php` (на проде через SSH)

### Изменить FAQ на одной категории
- TV `faq_data` — JSON формата `{"items":[{"q":"...","a":"..."}]}`. Менять там же где SEO.

### Добавить новую цель Метрики
- Через UI Метрики (OAuth-токен — read-only, программно создавать нельзя)
- В `form.js` отправить `ym('XXXX', 'reachGoal', 'goal_name')`

## Что находится в гите, а что только на проде

**В git (попадает на прод через `git pull` или scp):**
- Все файлы в `site/` (шаблоны, чанки file-based, сниппеты file-based, ассеты, иконки)
- Скрипты в `scripts/` (но они НЕ копируются на прод автоматически — деплоятся вручную если нужны)
- Документация в `ДОКУМЕНТАЦИЯ_РАЗРАБОТКА/` (на прод не идёт — лежит в корне репо)

**Только в БД (попадает на прод через дамп БД):**
- Контент DB-чанков: `Footer`, `Navbar`, `catalogHeader`, `boxCTABanner`, `boxGuaranteePSK`, `msProduct.content.PSK`, `contAdres`
- Шаблоны (содержимое колонки `content` в `modx_site_templates`)
- TV-определения (`modx_site_tmplvars`)
- TV-значения (`modx_site_tmplvar_contentvalues`)
- Ресурсы и их публикация
- Категории (`modx_categories`)

**Только на проде, ни в git ни в БД:**
- `site/core/config/b24.config.php` — webhook URL
- `site/core/cache/logs/b24_leads.log` — лог лидов
- `assets/uploads/`, `assets/images/products/`, `assets/images/rp/`, `assets/images/blog/` — файлы пользователей и курсов
