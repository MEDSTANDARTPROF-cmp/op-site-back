# ObrProfi — Регламент работы

> Связанные документы:
> - `УСТАНОВКА.md` — как развернуть проект на чистом компе
> - `СТРУКТУРА_ПРОЕКТА.md` — структура файлов, инструкции по элементам
> - `.1_пороли` — все доступы


---

## Архитектура сред

```
LOCAL (разработка)     -->     DEV (проверка)     -->     PROD (боевой)
http://localhost:8080          dev.obrprofi.ru            obrprofi.ru
Docker                         Beget                      Beget
БД: obrprofi                   БД: severmarin_devpr       БД: severmarin_prof
Кеш: ВЫКЛЮЧЕН                 Кеш: ВКЛЮЧЁН              Кеш: ВКЛЮЧЁН
```

### Главные правила

1. Изменения идут ТОЛЬКО в одном направлении: **LOCAL --> DEV --> PROD**
2. Никогда не редактируем код напрямую на DEV или PROD
3. Всегда проверяем на DEV перед деплоем на PROD
4. Всегда делаем бэкап PROD перед деплоем
5. Код элементов (шаблоны, чанки, сниппеты) — только в файлах, не в админке
6. Имена файлов и папок — только **латиница** (никакой кириллицы)

## Ежедневный рабочий процесс

### 1. Начало работы

```bash
# Запустить Docker
cd d:\Project\ObrProfi\docker
docker-compose up -d
```

Сайт доступен:
| Что | URL |
|---|---|
| Фронт | http://localhost:8080 |
| Админка MODX | http://localhost:8080/manager/ |
| phpMyAdmin | http://localhost:8081 |

### 2. Работа с кодом

**Кеш на локале ВЫКЛЮЧЕН** — изменения видны сразу, просто обновите страницу (F5).

| Что меняем | Где меняем |
|---|---|
| Шаблоны, чанки (HTML) | Файлы в `site\core\elements\` (.tpl) |
| Сниппеты, плагины (PHP) | Файлы в `site\core\elements\` (.php) |
| CSS, JS, картинки | Файлы в `site\assets\` |
| TV-поля, контент страниц | Через админку MODX |

> Подробные инструкции — см. `СТРУКТУРА_ПРОЕКТА.md`

### 3. Коммит и пуш

После каждого логического блока изменений — коммит и пуш:

```bash
cd d:\Project\ObrProfi

# Посмотреть что изменилось
git status
git diff

# Добавить изменённые файлы
git add site/core/elements/chunks/Theme/Footer.tpl
git add site/assets/css/style.css
# Или все изменения сразу:
git add -A

# Коммит с понятным описанием
git commit -m "Обновил Footer: добавил блок партнёров"

# Запушить на GitHub
git push
```

### Правила коммитов

| Правило | Пример |
|---|---|
| Коммит после каждого логического изменения | Не копить 10 правок в одном коммите |
| Описание на русском или английском | `"Исправил меню на мобильном"` |
| Не коммитить `.1_пороли` | Файл в `.gitignore` |
| Не коммитить `scripts/config.sh` | Содержит пароли, в `.gitignore` |
| Не коммитить `backup/` | Дампы БД тяжёлые, в `.gitignore` |

### Получить изменения коллеги

```bash
git pull
```

### 4. Завершение работы

```bash
# Коммит + пуш (если не сделали)
git add -A && git commit -m "Описание" && git push

# Остановить Docker
cd d:\Project\ObrProfi\docker
docker-compose down
```

## Git

### Что заливается в Git

| Заливается | НЕ заливается (.gitignore) |
|---|---|
| Файлы сайта (`site/`) | Пароли (`.1_пороли`) |
| Docker-конфигурация (`docker/`) | Скрипт с паролями (`scripts/config.sh`) |
| Скрипты деплоя (`scripts/`) | Бэкапы и дампы (`backup/`) |
| Документация (`.md`) | Кеш MODX (`site/core/cache/`) |
| Настройки VS Code (`.vscode/`) | Картинки товаров (`site/assets/images/products/`) |

### Первый запуск на новом компе (из Git)

```bash
# 1. Клонировать репозиторий
git clone git@github.com:MEDSTANDARTPROF-cmp/op-site-back.git d:\Project\ObrProfi

# 2. Скопировать config.sh с паролями (от коллеги или из .1_пороли)
cp scripts/config.sh.example scripts/config.sh
# Заполнить реальными паролями

# 3. Скачать дамп БД с прода
mkdir backup
bash scripts/pull-db-from-prod.sh

# 4. Запустить Docker
cd docker && docker-compose up -d --build

# 5. Выключить кеш (см. раздел Кеширование)
```

### Доступ к репозиторию

Для нового разработчика:
1. Создать аккаунт на GitHub
2. Попросить владельца добавить в организацию `MEDSTANDARTPROF-cmp`
3. Настроить SSH-ключ: https://docs.github.com/en/authentication/connecting-to-github-with-ssh

Все доступы (хостинг, БД, админка) — в файле `.1_пороли` (передаётся отдельно, не через Git!)

## Кеширование

| Среда | Кеш | Почему |
|---|---|---|
| **LOCAL** | Выключен | Изменения видны сразу без очистки |
| **DEV** | Включён | Проверяем как будет на проде |
| **PROD** | Включён | Скорость работы сайта |

### Выключить кеш (на локале)

phpMyAdmin (http://localhost:8081) → SQL:
```sql
UPDATE modx_system_settings SET value = '0'
WHERE `key` IN ('cache_default', 'cache_resource', 'cache_scripts', 'cache_db');
```
Затем: `rm -rf site\core\cache\*`

### Включить кеш (на DEV/PROD)

Кеш включён по умолчанию. Если был выключен — через админку:
Система → Системные настройки → `cache_default`, `cache_resource`, `cache_scripts`, `cache_db` = **Да**

### Очистка кеша после деплоя

После деплоя на DEV/PROD обязательно очистить кеш:
- Админка → Шестерёнка → Очистить кеш
- Или скрипты деплоя делают это автоматически

### После скачивания БД с прода

Если скачали свежую БД с прода (`pull-db-from-prod.sh`) — нужно снова **выключить кеш** на локале, т.к. на проде кеш включён.

## Метрика (Яндекс.Метрика)

Метрика работает **только на PROD** (obrprofi.ru). На DEV и LOCAL она отключена.

Реализовано условием в `core/elements/chunks/Theme/Head.tpl`:
```
[[++http_host:is=`obrprofi.ru`:then=`...код метрики...`]]
```

Если нужно добавить другие скрипты аналитики — оборачивать так же.

## Миграция LOCAL --> DEV

**Когда:** изменения проверены локально, готовы к показу.

### Что мигрируем

| Тип изменений | Способ | Нужна миграция БД? |
|---|---|---|
| Правка кода шаблонов/чанков/сниппетов | Файлы через SCP | Нет |
| Правка CSS/JS/картинок | Файлы через SCP | Нет |
| Создание НОВЫХ элементов | Файлы + дамп БД | Да |
| Создание/изменение TV-полей | Дамп БД | Да |
| Установка пакетов | Вручную на DEV | Да |

### Процедура

```bash
# 1. Деплой файлов на DEV (с автоматическим бэкапом)
bash scripts/deploy-to-dev.sh

# 2. Миграция БД (только если создавали новые элементы/TV)
bash scripts/migrate-db-to-dev.sh
```

### Проверка после деплоя
- Открыть https://dev.obrprofi.ru — проверить все изменённые страницы
- Открыть https://dev.obrprofi.ru/manager/ — проверить админку


---

## Миграция DEV --> PROD

**Когда:** изменения проверены на DEV, заказчик утвердил.

### Процедура

```bash
# 1. Полный бэкап ПРОД (обязательно!)
bash scripts/backup-prod.sh

# 2. Деплой файлов
bash scripts/deploy-to-prod.sh

# 3. Миграция БД (если нужно)
bash scripts/migrate-db-to-prod.sh
```

### Проверка после деплоя
- [ ] https://obrprofi.ru — главная страница
- [ ] Проверить все изменённые страницы
- [ ] https://obrprofi.ru/manager/ — админка
- [ ] Формы обратной связи (если затронуты)

### Откат (если что-то сломалось)
```bash
bash scripts/rollback-prod.sh
```

## Синхронизация БД PROD --> LOCAL

**Когда:** нужен актуальный контент с прода (менеджеры добавили страницы, товары и т.д.)

```bash
bash scripts/pull-db-from-prod.sh
```

**ВАЖНО:**
- Это **перезапишет** локальную БД
- После импорта нужно снова **выключить кеш** (см. раздел "Кеширование")
- После импорта нужно обновить `site_url` и `http_host` в контексте `web`:
  ```sql
  UPDATE modx_context_setting SET value = 'http://localhost:8080/' WHERE `key` = 'site_url' AND context_key = 'web';
  UPDATE modx_context_setting SET value = 'localhost:8080' WHERE `key` = 'http_host' AND context_key = 'web';
  ```

## Чеклист перед деплоем на PROD

- [ ] Все изменения проверены локально
- [ ] Файлы задеплоены на DEV
- [ ] Миграция БД на DEV (если нужна)
- [ ] DEV проверен (фронт + админка)
- [ ] Заказчик утвердил
- [ ] Сделан бэкап ПРОД (`bash scripts/backup-prod.sh`)
- [ ] Деплой на ПРОД выполнен
- [ ] ПРОД проверен (фронт + админка + формы)

## Скрипты

|---|---|
| `scripts/deploy-to-dev.sh` | Деплой файлов LOCAL --> DEV |

| `scripts/rollback-prod.sh` | Откат ПРОД из бэкапа |

## Правила безопасности

1. **Никогда не коммитить** файл `.1_пороли` в Git
2. **Всегда делать бэкап** перед деплоем на ПРОД
3. **Не редактировать** файлы напрямую на серверах — только через скрипты
4. **Не удалять** ядро MODX (`core/model/modx/`)
5. **Код элементов** правим в файлах, не в админке MODX
6. **Имена файлов** — только латиница, без пробелов и спецсимволов
7. **Метрика** — только на PROD, на DEV/LOCAL отключена
